# nixeljam - agent instructions

Milo's personal NixOS configuration, forked from anotherhadi/nixy.
Global agent rules still apply (see ~/.claude/CLAUDE.md / ~/.config/opencode/AGENTS.md); this file adds conventions specific to this repo.

## Structure

Features are enabled by importing their module, not by flipping option toggles.
System modules live in nixos/ and server-modules/, imported per host in hosts/<name>/configuration.nix.
User modules live in home/programs/ and home/system/, imported per host in hosts/<name>/home.nix.

Host globals (hostname, username, timeZone, locales, git identity, ...) live in hosts/<name>/variables.nix as config.var.*.
Read config.var.* inside modules instead of hardcoding host specifics.

README.md is autogenerated; edit .github/assets/README_template.md, never README.md directly.
Secrets are sops-nix, stored under each host's secrets/ directory.

## Building

Rebuild with `nixy rebuild` (= git add . && sudo nixos-rebuild switch --flake .; the host target is auto-selected by hostname).
Other subcommands: `nixy test`, `nixy update`, `nixy gc`, `nixy cb` (clean boot menu), `nixy listgen`.

Flakes only evaluate git-tracked files, so any new .nix file must be git-staged before it will build.
`nixy rebuild` stages automatically; raw `nixos-rebuild` / `nix build` does not.

Never commit something to main that has not been verified with a successful `nixy rebuild`.

## Git workflow

Use a risk-based workflow, not blanket branching.
There is no CI or branch protection, so branches only earn their keep for large or risky work.

Small, low-risk changes that are already built and switched live: commit straight to main and push.
Large, multi-host, secrets-touching, risky, or work-in-progress changes: use a feat/... or fix/... branch; a PR is optional (useful for a diff view or review before merging).
